# Maintained static mapping boundary

GhidraBoy is the only SM83 provider. GhiGBC compiles against its separate JAR (`compileOnly`); installation must supply that provider. The selected candidate is Ghidra 12.1.3, GhidraBoy facade/schema 2, GhiGBC adapter 1/native ABI 1/checkpoint 2. The historical 12.1.2 package remains a separate rollback tuple.

`ProgramMapping.inspect`, `physicalToStatic`, `staticToPhysical` and `exportBytes` are the supported provider calls. `BankMappings` normalizes SRAM ↔ SameBoy cart, retains partial ranges and all navigation candidates, and never derives hardware state from game memory. Runtime support remains ROM-only/MBC1/MBC3/MBC5. MBC2 static support is not runtime support; RTC/device/unknown bytes stay unresolved. PC remains the 16-bit CPU register.

The default explicitly selected view policy is `canonical`: unique actual file/loader-anchor storage, using a unique matching CPU-window alias when applicable. Multiple matching views remain unresolved. The context action “Inspect physical views and select mapping view” displays candidates and selects one address space for future captures. Missing portions remain unmapped. A conflict leaves existing user mappings untouched and records its reason. Mappings have one-snapshot lifespans. Integration does not remove/truncate any existing mapping.

A static snapshot records original file identity separately from current exported bytes and coverage. Exact binding requires current-export SHA256 equal to the immutable bytes loaded into SameBoy and full mapped coverage. Partial/unresolved exports cannot claim exact correspondence. Runtime profile recognition is an independent decision.

The SHA256-named adapter envelope includes static schema, ranges, current hash, coverage, selected view and block names. Renames/topology edits invalidate the next generation. `StaticMappingEnvelope`, `StaticMappingGeneration`, `MappingIssues`, `MappingOwned` and exact `MappingSnapshot` live at the captured snapshot; historical records are not rewritten. The agent accepts a versioned static snapshot with session/epoch validation, and its next completed capture records `BoundStaticGeneration`, referring to the Java-published immutable envelope. The agent does not resend the full envelope in a single RMI message. Native `MappingGeneration` remains the hardware observation generation, a separate namespace. Legacy `MappingReady` saved traces remain readable.

Conformance: `tests/ghidra/MappingContractTest.java` exercises the installed maintained provider with split/renamed blocks, patch identity, aliases, ambiguous views, explicit selection and unknown mapper state. `RealTraceTest` verifies user mappings, historical lifespans/reopen and physical breakpoints through real Trace RMI. Provider's own schema/topology/ownership/migration tests remain authoritative for static-only mechanisms.

Trace saving uses a bounded mapping barrier: the agent records its selected capture ID in MappingSaveBarrier, the Java mapping worker drains pending mappings and records MappingSaveReady, then stops writing until a new capture clears the barrier. The agent queries the acknowledgement through the normal trace-value API before saving. Snapshot transfers use a nonblocking sequential completion chain so they cannot block the mapping worker behind the saving callback. Known short transaction-lock races still use bounded retries; a barrier timeout is reported, never treated as a save pass.
