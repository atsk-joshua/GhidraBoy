# Optional profile API 1

Providers are trusted installed extension code, not a security sandbox. Only explicit local `profiles.json` modules are imported; ROM recognition never downloads or chooses code to execute. Each provider declares ID/version, API version, required capabilities, exact immutable-image SHA256 fingerprints and bounded physical capture ranges. GhiGBC owns machine locks, owner queue, execution ordering and trace publication. Providers receive copied observations, never Machine or native handles.

`ProfileSession` requires an unambiguous exact fingerprint and compatible capabilities. Capture declarations are limited to 64 ranges/64KiB. Pure decoders yield at most 4096 typed `Field`s with bounded text, physical sources and evidence kind (observed, decoded, hypothesis, model, uncertain). Every stored field contains provider/version/session/epoch/capture provenance; each trace object also carries its snapshot. Wrong/absent/failing providers leave controls, raw memory and raw history usable. Errors are visible in `ProfileError`; incomplete decoded results are discarded.

Static Program binding has no role in profile recognition. A valid runtime provider may decode while another/no Program is open. Navigation and additive bookmarking still require the capture's verified static mapping and matching Program URL.

Generic action service `GbcActionService` accepts a trace and immutable selected snapshot. The remote physical watch validates session, epoch, capture and paused state on the owner thread. Historical selections are observational. Every queued command validates its enqueue session/epoch; cancellation before execution prevents timed-out work from later changing the machine. Disconnect cancels remaining requests. Native/owner queues and native dropped-event accounting are retained.

`Machine.ProfileFields[index]` is generic and stores bounded UTF-8 JSON byte arrays. Legacy `UnitsData`/`CombatData` and `Machine.Units` are compatibility namespaces, not core semantics. The installed study provider may publish only the declared legacy attributes; generic readers never reinterpret unversioned data as a new provider revision. Static study decoders import neither Java nor GhiGBC.

Tests: `tests/test_profiles.py` uses a synthetic teaching-counter provider with no HP/unit assumptions. The real installed `RealTraceTest` confirms no study class is present and rejects independently stale session/epoch/capture requests without creating a breakpoint. Native bridge tests need no Java/Ghidra process.

Trace RMI12.1 correlates callback replies in FIFO order, without per-invocation IDs. The dispatcher therefore runs callbacks through one ordered worker, with at most64 outstanding callbacks. A full callback backlog closes the session rather than blocking the receiver or misattributing a reply. This is separate from the64-entry machine-owner queue and native event buffer. Native execution remains in bounded slices; resume does not occupy the callback worker for the duration of play. Tests explicitly verify that a slow success cannot swap with a later fast error.

Profile persistence uses explicit ProfileEncoding=field-batches-v1: Machine.ProfileFields[index].Data is a UTF-8 JSON array bounded to48000 bytes. ProfileRecordCount is the complete field count, not the number of batch objects. Each field still contains its own provenance. Earlier experimental single-field Data dictionaries remain raw legacy evidence when that encoding marker is absent. Batching avoids a pathological Ghidra write-behind index flush for thousands of per-field objects without dropping observations or extending timeouts.
