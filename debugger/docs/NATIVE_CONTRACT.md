# Native contract (ABI 1)

`gc_machine` is opaque outside C. It uses the exact pinned SameBoy headers in C; Python never reproduces SameBoy's private structure layout. Fixed-width exported records are declared in `native/ghigbc.h` and checked by real capture tests. Create returns an owned handle or null; destroy frees it. Negative return codes are argument/capacity errors; run returns a named safe-boundary stop reason. Caller-owned buffers are copied while holding one native mutex.

The agent reads the ROM and the 2304-byte CGB boot image once. The additive ABI-1 `gc_create_buffers` entry point copies those exact bytes into SameBoy before returning; it does not reopen their paths. ROM trace content, ROM eligibility and boot checkpoint fingerprints derive from these immutable input copies. Later replacement or removal of an input file cannot change an already loaded machine or its metadata. The file-path `gc_create` entry point remains for legacy native callers.

`gc_prepare_run` clears prior stop events and arms a one-instruction resume bypass. `gc_run` is bounded by run-call count and 8 MHz ticks, releasing the Python GIL via ctypes. Pause is the sole atomic lock-free operation. Ordinary instructions are counted by SameBoy's execution callback; HALT/STOP wait and interrupt entry have distinct stop reasons and do not invent instruction retirements.

The small core patch instruments direct CPU bus operations in `sm83_cpu.c`, around memory calls after cycle advancement. DMA and interrupt accesses cannot acquire a stale CPU writer. P0 watchpoints cover CPU-origin events only. I/O conflict emulation can produce multiple internal accesses and is not advertised as exact per-access hardware provenance. DMA/HDMA access watchpoints are not implemented.

A write event is an attempted access before SameBoy applies blocking or redirection. It preserves original physical identity and raw before/final-after bytes. Final-after is copied at the end of the instruction, not per-access commit evidence. Same-value writes count as access; change requires a valid physical byte delta. Inspector calls use `GB_safe_read_memory` and never invoke the CPU hook. The fixture verifies savestate equality before and after repeated inspector reads.

Captures copy CPU inspection memory, eight WRAM banks, two VRAM banks, and supported cartridge RAM under the same lock. CPU inspection uses safe-read semantics, not a claim about the next CPU bus read during DMA. Unusable memory and inactive RAM/RTC selectors are marked unknown in traces. ROM is immutable and recorded once. ROM-only/MBC1/MBC3/MBC5 are accepted; tested edges include MBC5 bank256, MBC1 ROM0 bank32, SVBK zero, echo aliases and boot identity. RTC selectors remain unknown. No DMA watchpoint coverage is claimed.

Full SameBoy checkpoints include JSON ROM/core/boot/model/clock metadata and state-file SHA256. Restore rejects mismatches, creates a new epoch, drops pending events, retains breakpoints, and releases keys. Tick/instruction sequence counters currently remain monotonic session counters across restore; checkpoint metadata records the original checkpoint time. Experiment edits require pause and a recovery checkpoint, and only operate on the emulator copy.

Experiment WRAM edits resolve the supplied CPU address (including echo aliases) to a physical bank/offset at the paused capture, then use `gc_edit_wram` to modify that physical byte. They bypass guest bus restrictions and CPU watch hooks and invalidate pending writer/call state. Invalid requests are rejected before any recovery artifact is created. Each successful edit has an immutable debugger-origin before/requested/actual-after record, a full pre-edit checkpoint, and its checkpoint SHA256. AF records the architectural masked result rather than assuming every requested flag bit was accepted.

Trace edit records live under `Machine.Edits`, separately from CPU access events under `Machine.Events`. They retain their original snapshot, epoch and recovery link after later restores and trace reopening. The runtime records edit intent in `edit.json` before modifying state, then records the actual result.

A restored capture retains an immutable parent-checkpoint identity: resolved path, state SHA256, source session/epoch and original checkpoint ticks. Later restores cannot rewrite an older capture’s parent. A checkpoint saved after restore records that parent as well. These optional provenance fields are compatible with prior schema2 checkpoints.
