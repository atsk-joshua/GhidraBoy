# Compiler support

Assembly `default` remains unchanged. No imported cartridge is automatically
assigned a C ABI. All CPU pointers remain 16 bits; far-pointer data is not an
alternative CPU pointer size.

The self-authored `src/test/resources/compiler/abi.c` and its emitted `abi.asm`
were compiled with GBDK 4.5.0's SDCC 4.5.1 #15267, from the official macOS arm64
archive SHA256 289ee60e46c5a2785a21e35533f84a5131ed4a063b21b0dbdedc9a10af15bf78.
Command: `sdcc -msm83 -S src/test/resources/compiler/abi.c -o src/test/resources/compiler/abi.asm`.
No compiler binary is redistributed. Generated fixtures contain no external
library implementation. The version string anomalously prints Mac OS X ppc;
the downloaded asset is the official arm64 build.

| Explicit compiler ID | Verified ordinary scalar selection |
| --- | --- |
| sdcc451-call0 | Legacy `__sdcccall(0)`: stack arguments from SP+2; caller cleanup; E/DE/HL:DE returns for 8/16/32 bits |
| sdcc451-call1-first8 | First argument A, second E or DE, remaining stack; A/BC/DE:BC returns |
| sdcc451-call1-first16 | First argument DE, second A or BC, remaining stack; same current returns |
| sdcc451-call1-first32 | First argument DE:BC, remaining stack; same current returns |

Choose the current variant by the first scalar argument width, using custom
storage where signatures differ across a ROM. Current ordinary stack arguments
are callee-cleaned; extrapop is unknown to allow Ghidra stack analysis rather
than inventing a fixed byte count. AF/BC/DE/HL are conservatively call-clobbered;
SP is restored under the convention. Tests ask the actual Ghidra compiler specs
for argument and return storage and compare mixed-width examples to emitted
instructions. This is not automatic signature recovery.

These are intentionally limited variants, not a universal SDCC ABI allocator.
Variadics, aggregates, unusual register-preservation attributes, and banked calls
require verified per-function custom storage. A historical pre-4.2 compiler was
not run; legacy behavior here is generated by explicit `__sdcccall(0)` on the
pinned current compiler. Banked calling support is not advertised. SDCC's change
of default in 4.2 must not be inferred merely from a ROM title or timestamp.
