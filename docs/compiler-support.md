# Compiler support

These are current bounded profiles. The [roadmap](roadmap.md) prioritizes broader
software-call semantics and [planned ABI/data requirements](static-analysis-spec.md#compiler-cartridge-and-saved-work-contracts).
Ghidra parameter model rules will be evaluated against emitted-code fixtures
before expanding custom allocation; no replacement is qualified yet.

Assembly `default` remains the import default. CPU pointers remain 16 bits;
far pointers are separate data. No ABI is inferred from a ROM title or date.
`CompilerAbi` and `GhidraBoyAbi.java` apply verified storage **per function**,
allowing mixed signatures without switching the entire Program compiler spec.

Assembly `__asm` treats F as killed by calls. Unknown assembly callees may
change flags; the caller must not reuse its incoming carry/zero flags across
a call without evidence. This is a conservative effect, not a claim about the
game's return convention. Native C may expose `extraout_F` when code branches on
callee flags. Give a proven flag-returning helper explicit per-function return
storage to explain that result; the default does not invent a C signature.
See [the call-flags regression](decompiler-call-flags.md) for the demonstrated
incorrect pre-call propagation and the remaining interpretation limits.

The self-authored fixtures in `src/test/resources/compiler` were generated by:

- GBDK 4.5.0, SDCC 4.5.1 #15267: `sdcc -msm83 -S abi.c -o abi.asm`.
- Actual historical GBDK 4.0.6, SDCC 4.1.6 #12539:
  `sdcc -mgbz80 -S legacy.c -o legacy.asm`. `gbz80` is that historical compiler's
  Game Boy target name. This is separate evidence from current `__sdcccall(0)`.

Official archive URLs/digests are pinned in `tools/dependencies.json`. No compiler
binary or external library implementation is redistributed. Tests compare emitted
allocation/cleanup with actual Ghidra storage and semantic decompiler results.

| Request profile | Established behavior |
| --- | --- |
| sdcc416 | Historical scalar stack from SP+2, caller cleanup, E/DE/HL:DE returns |
| sdcc451-call0 | Current explicit call(0), stack from SP+2, caller cleanup, legacy returns |
| sdcc451-call1 | First 8/16/32-bit argument A/DE/DE:BC; second scalar E or DE after first8, A or BC after first16; remaining byte-packed stack; callee cleanup; A/BC/DE:BC returns |
| sdcc451-variadic | Stack from SP+2, caller cleanup, current returns; explicit fixed parameters only |
| sdcc451-banked-callee | Callee entry stack from SP+6 due to helper frames, caller cleanup, current returns; helper itself is not modeled |
| sdcc451-preserves-bc | Tested one u8 parameter, u8/void return and preserved BC only |
| explicit | Exact register/stack storage, convention and purge supplied from independently checked emitted code |

The existing compiler IDs remain available for compatibility. Sibling prototype
models are available in assembly-default Programs. The generic Ghidra allocator
aligns some stack values differently from SDCC's packed stack; the per-function
workflow explicitly assigns storage and cleanup rather than changing global data
alignment. A 16-bit pointer consumes two bytes, including on a packed stack.

Aggregates need explicit storage. The maintained three-byte aggregate fixture
uses a hidden result pointer at `stack:2`, a `bytes:3` value at `stack:4`, void
return, and a five-byte purge. Supply the hidden parameter explicitly. A request:

```json
{"profile":"explicit","callingConvention":"__sdcc451_call1_first8","returnType":"void","parameters":[{"name":"result","type":"ptr","storage":"stack:2"},{"name":"value","type":"bytes:3","storage":"stack:4"}],"stackPurgeBytes":5}
```

This does not establish arbitrary aggregate lowering, all preservation attributes,
historical compiler releases, or general banked-call helpers. Inspect compiler
output and use explicit storage for those cases. The banked-callee profile is not
a far-call override. The separately supported MBC3 trampoline has narrower fixed
caller requirements; see analysis.md.

Future helper recognition must distinguish current register-target banked calls,
legacy inline-payload calls, restoring/nonrestoring wrappers and their flag effects.
GBDK 4.5.0's FAR_PTR container is 32 bits; a three-byte bank/address record is not
a universal far-pointer ABI. Reconstructed game assembly illustrates additional
conventions but does not identify the original toolchain. See
[versioned implementations and metadata sources](references.md#game-construction-and-metadata).


Finite `SoftwareCallModel` templates now distinguish inline/register target
extraction and three return-bank policies, including restoration that preserves
callee F while clobbering A/BC. These self-authored templates are explicit contracts, not recognized SDCC/GBDK
ABIs. The production integration below does not change compiler profiles or
default prototypes. Versioned compiler-helper qualification remains open under
SA-05; SA-01 status is tracked by its completion audit.

All existing compiler definitions now install `ghidraboy_software_call_v1` through
the provider injection library. It is selected by reviewed Program configuration,
not by choosing a compiler profile. The finite call templates still do not identify
GBDK/SDCC binaries. Dynamic per-site effects preserve independently derived callee
flags/registers and real frame operations under explicit premises; they do not
replace the default ABI globally. Contradictory target fixups, thunks, inline
contracts or stack cleanup require proof and review rather than guessed prototypes.


The additional neutral `ghidraboy_may_return_v1` fixup is an identity CALL backed
by a current code-derived return witness. It protects may-return facts without
introducing an ABI. These new paths are still under qualification; in particular,
canonical banked root decompilation and final installed/normal-window gates are
not complete. Compiler helper/ABI breadth is not expanded by this checkpoint.
