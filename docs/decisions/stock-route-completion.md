# Stock routes and bounded presentation storage

New ordinary, predicate, configured-domain and reviewed software-call requests use
stock CALLOTHER transport through their normal public methods. The shipped Tools
software-call apply action uses that same review/apply path. Explicit stock aliases
remain; `*LegacyComparison` entry points retain the historical companion dependency.
No analyzer automatically creates conditional entries for canonical Functions.

Read-only emission and explicit refresh select the persisted transport. Changing a
new-request default is not conversion authority. Conflicting stock/companion keys
are refused, not resolved by priority. Existing companion records and earlier stock
records remain untouched; unsupported executable use refuses. New application
preview also rejects incompatible saved stock authority before a reapply can remove
ownership. A read-only callback neither refreshes dependencies nor creates authority.

| Contract | Prior experimental stock format | Current format |
| --- | --- | --- |
| Carrier transport | `stock-callother-entry-2` | `stock-callother-entry-3` |
| Ordinary registration | `stock-ordinary-entry-1` | `stock-ordinary-entry-2` |
| Predicate registration | `stock-predicated-ordinary-calls-1` | `stock-predicated-ordinary-calls-2` |
| Configured-domain registration | `stock-software-call-domains-1` | `stock-software-call-domains-2` |
| Software registry | `stock-software-call-registry-1` | `stock-software-call-registry-2` |

Option keys remain separate from companion keys. Readers check the format before
interpreting proof fields. The changed meaning requires rejection even though JSON
field shapes mostly remain the same. Semantic engine/proof versions, hardware
userop indices, architectural widths, language **2.0**, its context schema and the
public physical mapping schema remain unchanged. No old record is relabeled.

Each admitted stock entry has independently owned, initialized, read-only one-byte
C9 presentation storage. It is not a byte mapping, game instruction, physical ROM
identity, RAM snapshot or hardware return word. Proof records retain real source
segments and producers decode those original instructions. Native call targets
resolve their physical source through recorded authority, not through carrier
storage. Export excludes structurally identified presentation storage from ROM
bytes. Invocation projections keep their original graph and selected step,
including earlier backedges. Fragments containing only inlined configured-call
effects retain their listing but do not acquire an unproved independent entry.

With analysis context present, the existing one-byte CALLOTHER/self-branch
constructor supplies the complete validated semantic payload. Losing context
exposes only one RET byte. That bound alone is insufficient: integrity-only
`uponentry` callbacks are installed on all shipped prototypes, including each
default model. They revalidate independently owned carriers and throw on damaged
context, convention, storage or authority. Normal unowned Functions receive only
a dead unique-space copy, with no architectural effect. The historical companion
prototype retains its separate dependency/transport checks. Successful graph
payloads contain original CALL/RET/frame effects exactly once.

The defined fault model includes retained ownership evidence with context loss,
convention change, their conjunction, missing/malformed registration, storage and
flow corruption, source drift and image replacement/old generations. Arbitrary
custom compiler-spec extensions or deletion of every ownership indicator are not
a universal guarantee. Actual DecompileResults and debug-recovered byte footprints
are required; elapsed time, bad-data diagnostics and plausible empty C cannot
establish refusal. The original mode-loss obligation remains no HighFunction and
no C with an integrity diagnostic.

Every baseline test instance remains an obligation, including repeated display
names. Two explicitly tagged optional tests exercise the companion-only canonical
selection protocol itself. Positive stock removal and post-mutation cancellation
cover their product lifecycle obligations. All other retained semantics stay in
ordinary `test`; stock does not need an opt-in flag or companion provisioning.
The external multiplicity-aware ledger is authoritative for exact dispositions.

Development uses only task-owned pristine runtime copies, isolated settings and
fresh current-language fixtures. Existing annotated language-1 Programs remain on
their original provider. This operational boundary is not an enforced core-open
refusal or a language migration implementation. Genuine SM83 1-to-2 preservation,
normal CodeBrowser/DecompilerProvider lifecycle and switch proof/lowering remain
separate release gates. The window capture script is not an acceptance checker.

Validation and exact candidate identities are recorded in the evidence index and
external STOCK-ROUTE-COMPLETION report. This decision does not claim product release
qualification or alter historical acceptance on its original runtime.
