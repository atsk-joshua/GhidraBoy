# W3b cyclic graph and invocation identity

This bounded extension builds on accepted W3a/G2. Its implementation does not
qualify W4/G3, all W3 families, or the product. Batch acceptance is recorded in the
durable workspace's W3b report and machine-readable receipts.

## Cyclic authority

`PredicatedCallGraph` uses stable control identity (CPU, physical fetch source,
mapper, invocation, live frame/SP and acyclic branch partition) separately from
finite joined value rows. Cyclic branch sites do not append path history. A row
retains its correlated incoming byte domain and complete register bindings;
register covers are never independently cross-multiplied into a joined state.
The transfer still uses `AbstractValues`, `ScalarAccess`, the actual instruction
p-code, mapper knowledge, and existing ordinary frame semantics.

The delta worklist adds distinct rows until no row remains. A second transfer
replay checks every retained row and successor inclusion before recording a
post-fixed point. Missing relation support and exhausted operation, control-node
or row budgets remain frontiers. Complete graph coverage means a closed bounded
reachability result; a recurrent row graph records possible nontermination and
retains returning paths. It does not turn a cycle or budget exhaustion into a
nonreturn annotation.

Joined rows reference a shared origin DAG and shared incoming-domain tables.
Origins preserve structural definitions, and conditional byte normalization is
accepted only after complete bounded relation evaluation. Flag dependencies not
transported by the existing byte-A native contract survive normalization and
branch partitioning. Callee restrictions inspect the per-row effects.

The main fixture counts `B & 7` in a real decrementing loop, stores C064, selects
mapper 1/2 by accumulator parity, calls physical CPU4000 and stores A to C065.
The structurally identical `B & 31` fixture checks control topology and provenance
depth independently of row growth. The row relation tracks distinct abstract
states; it contains no predecessor history chain. Actual measured sizes and
worklist counts belong in the batch receipts, not this contract.

## Exact continuation identity

`SoftwareCallEffects.postCallSuccessor` follows actual raw call/return edges and
checks the first resumed caller depth against the complete returned state.
`calleeInvocations` follows graph edges and selects vetoes by membership.
`ContinuationSummary.entryStep` names the entry explicitly. Application, registry
and native lowering use that identity rather than list position. Numeric IDs are
labels; they are not a forward-order eligibility predicate.

Exact cycle detection also includes the identity of each live call. A completed
callee occurrence cannot classify a later invocation as nonreturning; identities
leave the cycle key when their frames return. Root loop identity does not retain
a call history.

The bounded production witness has a normal callee RET and a caller loop whose
post-call successor was created earlier. Consistent graph renumbering and array
permutation must preserve emitted operations and real backedges. Nonlocal exits
continue to require explicit terminal/outcome state identity.

## Same configured site, multiple domains

`SoftwareCallDomains` owns an experimental group of 2..8 exact incoming domains
at the same physical configured CALL/RST. Each root and callee view belongs to a
Program/configuration/physical-site/frame invocation key. Every callback checks
consumed dependencies, native identity, view mappings and contracts, then
rederives the configured effect and continuation proofs. A display selection is
navigation state only and never selects executable premises.

This adapter reuses `SoftwareCallInjection.expand`, its agreed returned-register
contract, and exact continuation lowering. The configured instruction's original
hardware push precedes helper expansion. It supports real returning roots and
callees; nested configured-domain invocations remain an explicit refusal. Two
exact incoming-domain entries in one Program are not described as a single
unknown-input routine.

## Compatibility decision

Predicate graph and registration versions advance from 2 to 3: joined rows,
shared origin/domain IDs and convergence fields change experimental authority.
The envelope rejects earlier versions before decoding changed fields. No general
old-provider migration is implemented. One final current-format cyclic Program
must be saved and reopened in a separate read-only process.

The new configured-domain record starts at version 1. It stores configurations
and canonical semantic authority, not runtime polymorphic event objects to be
instantiated. Object keys and unordered register sets are canonicalized; execution
and event arrays retain their order. Exact continuation effects/lowering engine
versions advance, invalidating their prior dependency identities. The existing
configured registry fields retain their meaning and are rederived before use.

Native companion, SLEIGH, public mapping/language schemas and W2 ordinary record
fields remain unchanged. A correct graph and payload that cannot survive native
cyclic/joined recovery is a protected-boundary blocker, not permission to change
the protocol or suppress the contradiction.
