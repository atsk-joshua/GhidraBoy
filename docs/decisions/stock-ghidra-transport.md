# Stock-core transport qualification

The normal product target is unmodified Ghidra core plus GhidraBoy. This replaces
D2's provisional companion-as-deployment direction, without changing accepted
physical/state graphs, alias effects, frames, symbolic RAM or image generations.
Historical G2/G3 acceptance remains attached to its recorded patched runtime.
The stock execution has independent unresolved switch obligations; it is not a
complete stock product qualification or evidence that a custom core patch is necessary.

The candidate appends `gb_analysis_entry_v1` and adds a nonflowing, default-zero
analysis context. Canonical constructors require zero; the explicitly owned entry
has only CALLOTHER and a self-branch. This bounds raw native traversal before
stock flow-time injection. A retained failed candidate showed that removing the
context bypassed this hook and produced plausible, wrong C. The one bounded
correction adds a stock `uponentry` integrity guard: it revalidates authority and
emits only a dead unique COPY, never the graph or CPU/memory setup. Transport
version 2 rejects earlier candidate records. No hardware wrapper CALL or stack
effect is introduced.
The production proof emitters supply branches, frames, memory and physical callee
Functions. RAM carriers map the admitted generation snapshot in a separate view;
they never replace the source Function or establish a new executable generation.

Stock ordinary, predicate, configured-domain and exact software-call registries
have separate option keys and explicit transport versions. Old records and their
native-identity guards remain. No stock digest is substituted for nativeIdentity,
no old registration is refreshed implicitly, and the legacy entry convention
rejects stock software authority. New stock software ownership receipts record
the exact applied convention; old receipts without that field retain their
single legacy meaning. Rollback preserves later convention edits.

The context schema requires language **2.0**, following the pinned upstream major
version rule. CPU/register addresses, 16-bit pointers and established userop indices
are unchanged. Existing instruction patterns now have an explicit context predicate;
saved 1.0 parse trees must not be silently reused. No old-language translator or
general migration is provided or qualified by this task. Older annotated Programs
must remain with their original provider until a separate reviewed migration is
qualified. New records and current-format reopen are a separate obligation.

`StockEntries` and the existing Tools script provide ordinary navigation, source
navigation and explicit authority inspection. They do not replace the Decompiler
controller or own a separate native process. Conditional source/domain/generation
notices are Function comments rendered by the standard Decompiler. A current
provider proof alone is not a claim of correct native output. Warm normal-window
behavior must be reported from actual component observations.

The existing production conditional-call and cyclic witnesses work on the initial
pristine Mac candidate, as do the bounded memory/image and configured-domain
headless relations. Exact final-artifact status is recorded separately in the
external STOCK-GHIDRA-TRANSPORT report. Debug replay is not packed-wire capture.

The retained public JumpTable override reproduces incorrect selector normalization
at inputs 3, 4 and 5 despite six correct target addresses/labels. The nibble fixture
retains correct returned C but over-recovers its target range. Neither is a passing
switch qualification. A finite lowering would require proved selector/table/target
predicates absent from these existing entry producers; fixture result tables and
new core patches are not alternatives accepted here. No materialization fallback
was used for the already working entry mechanism.

The 501-instruction current-language corpus passes fresh decode and separate-process
save/reopen comparison. Reopening the corpus saved by the accepted 1.0 provider
logs a missing old-language specification, performs an in-memory language update,
runs the 501-instruction check successfully, and discards changes under read-only
mode. This is neither explicit old-language refusal nor an annotated-Program
migration pass. Do not infer preservation from the check's post-update snapshot.
Host user settings and
projects were isolated; Ghidra's default host temporary/cache roots remained in
use. The resolved JAR inventory and key loaded class origins were audited against
the pristine runtime and exact provider payload, rather than inferred from cache
or companion-marker absence.
